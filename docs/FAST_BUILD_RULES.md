# Fast Build Rules｜减少无用审查，增加有效开发

## 必须做

- 先完成 Asset Sprint 最低线；
- 缺素材时主动生成或寻找合法资源；
- 缺 API 时使用 Mock 和可替换接口；
- 每完成一段就实际运行、截图和修复；
- 页面使用真实内容和真实状态；
- 保持 MVP 垂直闭环优先。

## 只保留四个轻量记录

- `docs/STATUS.md`：当前已完成；
- `docs/TODO.md`：接下来 10—20 项；
- `docs/ASSET_SOURCES.md`：实际使用素材来源；
- `docs/KNOWN_ISSUES.md`：真实问题。

## 不要做

- 不写长篇 ADR、研究综述、企业级合规报告；
- 不为尚未使用的资源做审查；
- 不一开始读取完整聊天和全部可选源码；
- 不设计微服务、多云、复杂权限和大规模评测平台；
- 不反复向用户确认非阻塞细节；
- 不用假进度、假客户 Logo、假评价和假数据；
- 不以“审查还没完成”为理由停止可逆的本地开发。

## 最小实用检查

仅对实际进入生产的内容做一次：

1. 来源是否明确；
2. 是否允许商业使用；
3. 是否需要署名；
4. 是否包含敏感信息或恶意代码；
5. 是否有更轻、更稳定的替代。

检查通过后继续开发，不追加重复审批层。
