# AIPPT MVP 工作台同步、商业闭环与首页叙事整改文档

> 用途：作为 Codex 的直接开发依据。  
> 范围：在现有 MVP 上增量修复，不推翻品牌视觉，不重写已可用的生成器与编辑器。  
> 核心目标：先解决项目数据串线和流程不同步，再补齐最小商业闭环，最后完成首页电影式滚动叙事。

---

## 1. 当前版本结论

AIPPT 已经具备完整的表面流程：

```text
营销首页 → 项目列表 → 创建中心 → 蓝图/智能体 → 编辑器 → 质量中心 → 交付中心
```

现有视觉语言已经较清晰：深黑背景、荧光黄绿、米白画布、网格、硬边卡片、切角按钮、琶洲夜景与“页核”IP。此次整改不应重新设计品牌。

当前真正阻碍产品继续迭代的不是页面数量，而是三类结构性问题：

1. **项目上下文和数据不同步**：不同项目内容、质量报告和导出状态可能串线。
2. **工作台信息架构不成立**：全局功能与单项目制作阶段混在同一侧边栏。
3. **商业闭环缺失**：没有套餐、点数、升级、购买、权益解锁和用量记录。

首页 Hero 另有一个独立问题：当前是静态海报式构图，还没有形成真正的电影式滚动叙事。

# 2. P0：必须最先修复的数据与同步问题

## 2.1 跨项目数据污染

截图中已经出现明显串线：

- 创建中心输入的是“华南区域管理层 2025 年度经营分析与增长规划”；
- 编辑器项目名称却是“电气工程专业毕业答辩 PPT”；
- 编辑器封面副标题仍保留“2025 年度经营分析与增长规划”；
- 质量中心提示“效率提升的数据口径”“90 天行动计划缺少负责人”，明显属于经营分析项目。

这说明需求、页面内容、质量报告或模板状态至少有一部分没有按项目隔离。

### 必须整改

- [ ] 所有业务数据必须绑定 `projectId`。
- [ ] 页面级数据和质量问题必须额外绑定 `slideId`。
- [ ] 检查结果、导出结果和异步任务必须绑定 `revision`。
- [ ] 禁止仅依赖 `lastOpenedProject`、模糊的 `currentProject` 或全局单例缓存决定当前项目。
- [ ] 旧异步请求完成时，必须验证 `projectId + revision` 后才能写回。
- [ ] 模板默认文案必须在生成后彻底清理，不得残留到其他项目。
- [ ] 创建两个完全不同的项目进行隔离回归测试。

## 2.2 缺少唯一项目数据源

目前创建中心、编辑器、质量中心和交付中心看起来像分别维护自己的项目状态。

### 统一项目模型

至少应有一份统一项目对象：

```ts
interface PresentationProject {
  id: string;
  title: string;
  brief: {
    originalPrompt: string;
    topic: string;
    audience?: string;
    purpose?: string;
    scenario?: string;
    language: string;
    pageCount: number;
    sourceFileIds: string[];
  };
  outline: OutlineItem[];
  theme: ThemeSpec;
  slides: SlideSpec[];
  activeSlideId?: string;
  generationStatus: JobStatus;
  revision: number;
  qualityReport?: QualityReport;
  exportJobs: ExportJob[];
  createdAt: string;
  updatedAt: string;
}
```

### 必须整改

- [ ] 建立统一 `ProjectStore / ProjectService / Repository`。
- [ ] 所有阶段只读写同一份项目数据。
- [ ] 创建项目时立即持久化并获得真实 `projectId`。
- [ ] 刷新、前进、后退、直接打开深链接后，项目上下文保持一致。
- [ ] 项目名称、页数、缩略图、当前页、质量报告和导出状态必须从同一数据源派生。
- [ ] 不得让真实项目仅依赖组件 state 或 localStorage 保存。

## 2.3 缺少版本和失效机制

当前编辑页面后，质量中心可能仍展示旧的 92 分；交付中心也可能使用旧缩略图和旧导出缓存。

### 版本规则

```text
修改需求
→ 蓝图、页面、质量报告、导出结果标记为可能过期

修改蓝图
→ 受影响页面、质量报告、导出结果标记为过期

修改任何页面
→ 质量报告和导出结果标记为过期

重新完成质量检查
→ 报告绑定当前 revision

重新导出
→ 文件绑定当前 revision
```

### 必须整改

- [ ] 项目每次有效修改递增 `revision`。
- [ ] `qualityReport.revision` 必须存在。
- [ ] `exportJob.revision` 必须存在。
- [ ] 过期报告不能继续显示“已达到专业交付标准”。
- [ ] 交付中心必须说明即将导出的具体版本。
- [ ] 页面修改后，编辑器、检查和交付状态立即同步。

建议界面文案：

```text
当前演示版本：v13
上次质量检查：基于 v12，演示已修改
[重新检查]
```

```text
即将导出版本：v13
当前质量报告基于 v12
[先检查] [仍然导出]
```

## 2.4 异步任务没有统一状态机

生成、质量检查和导出都属于异步任务，必须可恢复、可重试、不可串项目。

### 统一状态

```text
idle → queued → running → success
                     ↘ failed
                     ↘ cancelled
结果版本变化后 → stale
```

每个任务至少记录：

```ts
interface ProjectJob {
  id: string;
  projectId: string;
  revision: number;
  type: 'generate' | 'quality-check' | 'export';
  status: 'idle' | 'queued' | 'running' | 'success' | 'failed' | 'cancelled' | 'stale';
  progress?: number;
  startedAt?: string;
  completedAt?: string;
  error?: string;
}
```

### 必须整改

- [ ] 离开页面后任务继续执行或可恢复。
- [ ] 刷新后能恢复任务状态。
- [ ] 防止重复点击创建重复任务。
- [ ] 失败可重试，不应永久卡死。
- [ ] 旧任务不得覆盖新版本结果。
- [ ] A 项目的任务不得写入 B 项目。

# 3. P1：重构工作台信息架构

## 3.1 当前侧边栏混合了两类概念

现有侧边栏把以下内容放在同一级：

```text
项目列表
创建中心
演示蓝图
Agent Studio
编辑器
质量中心
交付中心
偏好设置
```

其中“项目列表、偏好设置”是全局功能；“需求、蓝图、编辑、检查、交付”是某个项目的制作阶段；`Agent Studio` 是 AI 能力，不应成为一个独立阶段。

## 3.2 新的信息架构

### 全局工作台导航

```text
项目
模板
品牌与素材
套餐与用量
偏好设置
```

### 打开具体项目后的阶段导航

```text
需求 → 蓝图 → 生成 → 编辑 → 检查 → 交付
```

阶段状态至少包括：

```text
未开始
进行中
已完成
需要更新
执行失败
```

示例：

```text
需求 ✓  蓝图 ✓  生成 ✓  编辑 ●  检查 需要更新  交付 未开始
```

### 必须整改

- [ ] 创建中心只负责创建新项目，不再是长期一级导航。
- [ ] 蓝图、编辑、检查和交付必须属于具体 `projectId`。
- [ ] 不允许未选择项目时直接进入某个隐式项目的质量中心或交付中心。
- [ ] 阶段导航应清楚表示当前步骤和失效状态。

## 3.3 统一 ProjectShell

所有项目页面使用统一壳层，持续显示：

```text
项目名称
保存状态
当前版本
质量状态
Free / Pro 与剩余点数
分享
导出
```

推荐路由：

```text
/projects/:projectId/brief
/projects/:projectId/outline
/projects/:projectId/generate
/projects/:projectId/edit
/projects/:projectId/review
/projects/:projectId/export
```

按现有路由框架适配，但 URL 必须显式包含 `projectId`。

## 3.4 合并 Agent Studio

`Agent Studio` 不再作为全局一级页面。将“页核”变成项目内持续存在的上下文 AI 助手。

不同阶段承担不同能力：

```text
需求：澄清目标、听众、场景和边界
蓝图：调整故事线、章节和页面数量
编辑：修改元素、当前页、章节或整份演示
检查：解释问题、定位并协助修复
交付：生成讲稿、摘要和分享文案
```

编辑器右侧建议改为：

```text
AI 修改 | 属性 | 设计
```

AI 修改范围必须清晰：

```text
修改当前元素
只修改当前页
调整当前章节
统一整份风格
```

每次 AI 操作必须支持撤销，且不得在“只修改当前页”时重写整份演示。

# 4. 各页面需要修复的问题

## 4.1 项目列表

当前问题：

- “空状态、加载中、异常状态”被做成正式标签；
- 顶部和内容区存在重复搜索；
- 项目卡信息不足；
- 多个缩略图几乎是同一模板；
- 新建入口重复；
- 左下角“已就绪”长期固定，没有真实状态价值。

### 必须整改

- [ ] 开发状态不再作为用户标签，按真实请求自动显示。
- [ ] 只保留一套搜索。
- [ ] 项目卡使用真实封面缩略图。
- [ ] 项目卡显示阶段、页数、待处理问题、最后编辑时间和导出状态。
- [ ] 支持继续编辑、重命名、复制、导出和删除。
- [ ] “已就绪”改为真实的保存中、已保存、失败、生成中、检查中或导出中。

项目卡示例：

```text
编辑中 · 第 4/6 阶段
12 页 · 2 条待修复建议
8 分钟前编辑 · 已导出 PPTX
```

## 4.2 创建中心

当前问题：

- 一句话输入后直接执行，缺少需求确认；
- “开始理解”不说明下一步；
- 没有页数和汇报时长；
- 文件上传状态不完整；
- 无生成成本和余额提示；
- “页核”区域偏装饰，没有真实执行状态。

### 必须整改

AI 自动推断并让用户快速确认：

```text
面向：华南区域管理层
目的：年度经营分析
页数：12 页
时长：20 分钟
风格：专业、数据驱动
资料：已上传 2 份
```

- [ ] 将按钮改为更明确的“生成演示蓝图”。
- [ ] 显示下一步会生成的内容。
- [ ] 支持推荐页数、自定义页数、汇报时长和生成模式。
- [ ] 每个上传文件显示上传中、解析中、已解析、解析失败、已用于生成。
- [ ] 显示预计页数、预计点数和当前余额。
- [ ] “页核”显示真实状态，例如正在识别目标、等待确认、已准备生成。

## 4.3 编辑器

当前问题：

- 用户原始指令被直接当成演示标题；
- 模板占位内容残留；
- 页面布局过于重复；
- 右侧空状态利用不足；
- AI 修改范围不明确；
- 缺少 AI 操作版本历史；
- 看不到当前页和整份演示的质量状态；
- 保存反馈过于简单。

### 必须整改

- [ ] 将原始指令与正式演示标题分离。
- [ ] 增加模板占位符和主题不一致文本扫描。
- [ ] 页面类型至少覆盖封面、问题、数据、流程、对比、案例、行动计划、总结等。
- [ ] 未选中元素时显示“优化当前页、换布局、减少文字、增加视觉、转为图表”等高频入口。
- [ ] AI 修改支持保留内容、允许改写、保留布局、允许换版、预览和撤销。
- [ ] 增加页面级或项目级版本历史。
- [ ] 编辑器显示“当前页问题数”和“整份演示需要重新检查”。
- [ ] 保存状态包括保存中、已保存、失败、离线和最后保存时间。

编辑器顶部按钮应根据状态变化：

```text
未检查：去检查
报告过期：重新检查
报告有效：去交付
```

不再固定使用含义模糊的“检查并交付”。

## 4.4 质量中心

当前问题：

- 实际内容明显串线，仍给出 92 分；
- “事实准确性通过”“版权与来源通过”缺少依据；
- 分数计算不可解释；
- 一键修复含义不清；
- 定位和修复闭环不完整；
- 报告没有版本有效性。

### 必须整改

质量检查至少包含：

```text
项目主题一致性
页面标题与需求一致性
模板占位符残留
跨项目内容污染
重复页面和重复观点
内容完整性
来源可验证性
文本溢出
版式可读性
```

状态必须区分：

```text
已核对
存在风险
无法自动验证
需要人工确认
```

- [ ] 分数显示计算依据和主要扣分项。
- [ ] 涉及事实和版权的问题不得无依据标记“通过”。
- [ ] “一键修复”拆为查看方案、安全自动修复和定位页面。
- [ ] 点击定位后打开正确项目、页面和元素。
- [ ] 修复后问题状态和分数更新。
- [ ] 报告显示基于哪个 revision，过期时明显提示。

## 4.5 交付中心

当前问题：

- 不显示当前项目和版本；
- PDF/PNG 页数可能硬编码为 5；
- 预览可能不是当前版本；
- 没有导出任务状态；
- “原生对象”表达不清；
- 分享权限不明确。

### 必须整改

- [ ] 显示项目名称、版本、页数、最后保存时间和质量报告状态。
- [ ] 页数从当前项目动态读取。
- [ ] 预览和导出绑定 `projectId + revision`。
- [ ] 页面修改后旧预览标记过期。
- [ ] 显示准备资源、处理字体、渲染页面、生成文件、完成等导出进度。
- [ ] 失败可重试，历史导出可重新下载。
- [ ] 将“原生对象”解释为“文字、图片和形状可在 PowerPoint 中继续编辑”。
- [ ] 分享链接至少说明公开范围、下载权限、过期和撤销方式。

# 5. P2：补齐最小商业闭环

商业化必须建立在项目同步和导出稳定之后。当前不是只缺定价页，而是缺完整闭环：

```text
理解价值 → 免费生成 → 看见额度 → 遇到具体限制 → 升级 → 完成购买 → 返回原任务 → 权益立即生效
```

## 5.1 套餐建议

套餐数字作为早期测试配置，必须集中配置。

### Free

```text
价格：¥0
注册赠送：300 AI 点
单份演示最多：10 页
活跃项目最多：3 个
标准文本和图片模式
首次允许带 AIPPT 标识的可编辑 PPTX
```

### Pro

```text
价格：¥29/月，¥268/年
每月：3000 AI 点
单份演示最多：30 页
高级文本和图片模式
全部模板
无品牌可编辑 PPTX
PDF / PNG 高清导出
更长版本历史
```

团队版本轮只保留“联系合作”入口，不开发团队权限。

## 5.2 必要商业页面和入口

至少实现：

```text
/pricing
/account/usage
/account/billing（可与 usage 合并为一个设置页）
/checkout/success
/checkout/cancel
```

工作台顶部显示：

```text
Free / Pro
剩余 AI 点数
升级 Pro
```

## 5.3 AI 点数与权益

建立统一能力：

```ts
getCurrentPlan(userId)
getEntitlements(userId)
canUseFeature(userId, feature)
getCreditBalance(userId)
estimateCreditCost(userId, action)
reserveCredits(userId, action)
settleCredits(reservationId)
refundCredits(reservationId)
```

至少覆盖：

```text
最大页数
最大项目数
标准或高级文本模型
标准或高级图片模型
高级模板
带品牌或无品牌 PPTX
版本历史
```

点数扣减要求：

- [ ] 原子扣减；
- [ ] 余额不得为负；
- [ ] 重复请求不得重复扣费；
- [ ] 生成失败自动返还；
- [ ] 每笔消费绑定项目和任务；
- [ ] 前端和服务端均校验权益。

## 5.4 自然升级触发点

只在用户产生具体需求时提示升级：

```text
点数不足
超过免费页数
使用高级模型
使用高级模板
无品牌 PPTX 导出
高级图片生成
更长版本历史
```

建立统一升级弹窗，并根据触发原因显示不同文案。

支付成功后必须回到原项目和原操作，例如：

```text
点击无品牌导出
→ 升级 Pro
→ 完成购买
→ 返回当前项目交付中心
→ 自动恢复无品牌导出选项
→ 继续导出
```

## 5.5 支付实现范围

开发阶段使用明确标识的 `MockBillingProvider`：

```text
选择月付或年付
→ 开发环境模拟开通
→ 更新套餐和点数
→ 返回原任务
```

要求：

- [ ] 模拟支付不得伪装成真实支付。
- [ ] 建立统一 `BillingProvider` 接口，方便后续接入正式平台。
- [ ] 未配置正式支付时，生产环境不得直接显示虚假的支付成功。
- [ ] 暂不开发发票、优惠券、企业账单和复杂退款后台。

至少记录：

export_clicked

# 6. P3：首页与电影式滚动叙事

## 6.1 当前问题

首页视觉辨识度较高，但 Hero 本质上还是静态舞台：夜景、轨道、卡片和页核同时出现，缺少滚动推进的剧情和空间变化。

同时存在：

- 标题“从一句话，到五页……”把产品限制为固定五页；
- “启动观测台”有品牌感，但任务表达不够直接；
- 一级导航缺少案例、定价和登录；
- 模板区只展示相似封面，缺少真实内页和结果证明；
- 页面缺少套餐、FAQ、信任和法律入口；
- 左下角女性头像与“页核”形成双 IP 冲突。

## 6.2 Hero 目标

将 Hero 改为：

```text
一句话进入
→ 页核理解目标
→ 搭建蓝图
→ 组织页面
→ 检查和交付
→ 免费创建演示 CTA
```

使用一个统一滚动进度驱动五幕叙事，而不是多个无关定时器。

### 页面结构

```text
HeroScrollScene：约 420vh～500vh
└─ HeroStage：sticky; top: 0; height: 100vh
   ├─ 远景琶洲夜景
   ├─ 中景网格、光晕和轨道
   ├─ 前景目标、蓝图、页面和交付卡片
   ├─ 页核核心层
   ├─ 分幕文案
   └─ 最终 CTA
```

### 五幕节奏

```text
0%～18%：一句话进入系统
18%～38%：理解目标、听众和边界
38%～60%：搭建故事线和页面蓝图
60%～82%：卡片聚合为可编辑演示
82%～100%：检查、交付和 CTA 收束
```

### 必须实现

- [ ] `sticky 100vh` 固定舞台。
- [ ] 远景、中景和前景有克制的速度差。
- [ ] 卡片具有进入、停留和退出区间。
- [ ] 背景持续推进时，卡片进行反向缩放补偿。
- [ ] 文案不是统一淡入，而是分幕进入。
- [ ] 桌面端增加轻量缓动指针视差。
- [ ] 移动端关闭指针视差并减少同时显示的卡片。
- [ ] `prefers-reduced-motion` 下保留完整内容和 CTA，只降低位移、缩放和旋转。
- [ ] Hero 结束后自然进入下一模块，不突然硬切。
- [ ] 不使用视频或整页截图假装交互。
- [ ] 不引入重量级 3D/WebGL 框架，优先复用现有动画依赖。

# 9. 必须通过的验收测试

## 9.1 双项目隔离

创建：

```text
项目 A：华南区域经营分析
项目 B：电气工程毕业答辩
```

验证：

- [ ] A 的文字、缩略图、质量问题和导出不得出现在 B。
- [ ] B 的任何操作不得改变 A。
- [ ] 刷新、返回和直接访问链接后仍正确。

## 9.2 版本失效

```text
完成质量检查
→ 修改第 3 页
→ 报告立即标记过期
→ 重新检查
→ 新报告绑定当前 revision
→ 导出当前 revision
```

## 9.3 异步恢复

- [ ] 生成中离开页面，再返回后可继续查看进度。
- [ ] 检查或导出失败可重试。
- [ ] 旧任务不得覆盖新版本。

## 9.4 商业闭环

```text
Free 用户创建演示
→ 查看点数与预计消耗
→ 选择高级功能
→ 出现对应升级说明
→ 模拟升级 Pro
→ 返回原项目和原操作
→ 权益立即生效
→ 无品牌导出成功
```
